# Skill: Meta Skill — Building Skills That Build Skills

**Expert:** The team's skill-creation discipline (distilled from TJ Robertson's "meta skill" method, adopted 2026-09-27).
**Lens:** Think like a skill architect: a good skill is a capability, not a script. Build skills that make the team smarter, then let the team use them intelligently.
**Applies to:** creating new expert lenses, improving existing skills, onboarding new team members, any repeated struggle that a capability would fix.
**Owner:** Head of HR (@head-of-hr) — the team's designated skill creator.

## Core philosophy

Don't hand-write every skill by hand. Build one meta skill — a skill whose job is creating other skills customized to this team's life and business — and let it do the work. Feed it source material (a video transcript, a playbook, a post-mortem), give it your rules, and let it draft the skill. Then review like an editor, not a typist.

## The rules

1. **Propose your own rules and push back.** Never let the builder do everything on defaults. Come with your own rules for what a good skill looks like, argue with the draft, and iterate. The skill is only as opinionated as you are.

2. **Describe the task, provide all context — don't over-specify behavior.** Instead of detailing exactly how the skill should behave step by step, describe what it's for and give it everything it needs to know. Trust it to make intelligent decisions in the moment. Over-scripted skills are brittle; well-contextualized ones adapt.

3. **Ground every skill in official documentation.** New skills must follow the established standards for skill format and structure — no folk formats that only one person understands.

4. **Declare what the skill needs access to.** Every skill should state plainly which systems, tools, and data it requires. If it needs something it can't reach, that's a task for the CTO, not a silent failure.

5. **One skill per specific concern.** Don't bundle. A focused skill gets used; a grab-bag skill gets ignored. When a new concern appears, create a separate skill for it.

6. **Skills that ask Jesse questions get their own dedicated skill.** How the team handles asking the investor anything — when it's warranted, how to frame it, what format to use — is important enough to be a standalone skill, not a paragraph buried in another one. Coordinate with Exec PM, who owns Jesse contact.

7. **Inspect the system, find the gaps, share across skills.** The meta skill doesn't wait to be asked. It looks at how the team is actually set up, identifies where a new skill would help, builds it, and shares what it learns so other skills get better too. Coordinate with the CRO, whose research surfaces the opportunities.

## When to build

- A teammate repeatedly struggles with the same kind of work (skill gap, not effort gap).
- A new project needs a capability nobody on the team has.
- A post-mortem reveals a mistake a checklist or lens would have prevented.
- A new team member joins (onboarding is a skill-building moment).

## Quality bar

Every skill ships with: a clear name, the expert or source it's drawn from, what it's for, when it applies, and the rules above baked in. If you can't explain what the skill is for in one sentence, it's not a skill yet.
